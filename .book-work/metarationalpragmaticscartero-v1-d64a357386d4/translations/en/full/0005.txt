CHAPTER 09
Diagnosing Errors
Why Not Every Failure Requires a New Representation
An agent answers incorrectly. What must change? If every error leads to building an interpreter, the library quickly becomes a collection of exceptions. If no error can modify representations, the agent remains trapped within the distinctions originally designed. Diagnosis is the link between these extremes.
In the proposed model, an incident is preserved with its input, the representation actually used, interpreter version, prediction, observed result and observation conditions. The difference between prediction and result does not establish the cause by itself. It opens a bounded investigation.

These causes can coexist. A faulty interpreter can also conceal missing information. Diagnosis must therefore remain revisable, rather than become a permanent label assigned by a classifier.
Collision as a Witness of Insufficiency
A relevant collision occurs when the same representation corresponds to incompatible answers under the same test and conditions. Identifying it requires checking precisely those conditions. It is not a collision if one example uses a different rule or the questions differ.
In a deterministic microworld, two histories can supply an exact witness. In a stochastic environment, two different results are insufficient: the same distribution can produce both. There, a difference between distributions must be proved or estimated, with enough repetitions and control of relevant conditions.
A practical procedure would first seek collisions in the execution log. It would then try to reproduce the pair in a controlled environment. If reproduction confirms the difference, the agent would generate hypotheses about lost information. Otherwise, the incident remains open or is reclassified.
Counterexample-Guided Refinement
CEGAR, counterexample-guided abstraction refinement, supplies an important discipline: an abstraction is verified and an abstract counterexample is compared with concrete behavior. If that counterexample is spurious, the abstraction can be refined to eliminate it [
Clarke2000
MRP would adopt the loop's idea without claiming that every prediction error is the same mathematical object. In verification, a false alarm may require more precision. In learning, a false prediction may require new data, a different distribution or a program correction. Identifying the failure type precedes choosing a refinement.
A proposed refinement must explain why the current representation confuses the cases. “Add another component” is insufficient explanation. “Preserve the last operation for each person–resource pair because operation order changes the answer” is an operational hypothesis.
Minimal and General Distinctions
The program “recognize exactly the history that failed” separates any memorized case. Usually, however, it is not the distinction sought. A program tracking the last relevant operation can separate an entire family of cases. The difference between the two appears on new examples, not the initial incident.
Proposing a distinction must therefore be followed by generating contrastive cases. Change the person's identity, add irrelevant events, repeat an operation or interleave other resources. The program should preserve what matters and ignore variations irrelevant to the rule studied.
These transformations are not arbitrary. If repeating an operation changes the protocol's meaning, it cannot be treated as an invariance. The family of accepted transformations forms part of the test specification. Even constructing tests can introduce mistaken assumptions.
Information That Cannot Be Recovered
Suppose the history has been discarded and only an unordered set remains. If two valid histories produce the same set, no program reading only that set can reliably reconstruct which history occurred. We can estimate a probability from frequencies, but this does not recover the actual event.
MRP must be able to respond: “I identified the necessary distinction, but no longer have the information needed to compute it.” This state is a useful result. It can prompt a change in memory policy or a request for a new event without fabricating a retrospective solution.
In an implementable system, diagnosis would produce one of three main outputs: a repair computable from existing information, an experiment that can supply missing information or an explicit limit. Promoting every incident into the first category would turn the architecture into a generator of unverifiable explanations.
What Can Be Measured
Diagnostic quality has its own test set. In microworlds, we can separately inject implementation errors, collisions, missing observations and rule changes. We measure how often the agent identifies the appropriate mechanism and how much the investigation costs.
This test differs from final accuracy. A system can sometimes reach the correct answer through the wrong repair, which will fail later. For MRP, what matters is whether the improvement addresses the actual cause of difficulty, not merely whether a one-off score rises.
CHAPTER 10
Interpreter Induction
What Is Learned and What Is Supplied
An initial MRP system need not invent machine language, logic or every basic operation. It can receive a function core and learn new compositions. Learning's contribution must be described precisely: which primitives existed, which structures could be expressed and which programs were discovered.
For event histories, primitives may include filtering by a field, comparing two values, selecting an extremum, counting, joining by a key and applying a transition rule. A type limits admissible inputs: selecting the last record takes an orderable sequence, not a probability or an isolated proposition.
Types reduce search and prevent some errors, but do not establish intent. A program can be well typed and select the first record instead of the last. Structural correctness is a necessary condition for certain operations, not a certificate for the entire solution.
Searching a Finitely Described Language
Induction can begin by enumerating short compositions. If there are roughly b choices at each position and length d is allowed, the number of candidate sequences may grow on the order of b to the power d. Types, symmetries and examples eliminate some combinations without removing the combinatorial difficulty.
A guided generator can prioritize programs that seem appropriate to the incident. For example, the difference between two histories with identical elements in different orders suggests order-sensitive operations. This heuristic does not guarantee success; it offers a verifiable way to reduce computation.
An LLM can participate as a generator of such hypotheses. The potential advantage is rapidly proposing compositions that would be expensive to enumerate. The disadvantage is that it may supply additional information from training, produce fragile programs and dominate the entire system's contribution. Evaluation must include a variant using the same LLM, tools and budget but lacking MRP's consolidation mechanism.
A Selection Criterion Beyond Fitting Examples
A selection function can combine error, description complexity and execution cost. No weights are universally correct. They express the trade-off chosen for the application and must be published with the results.
Score(candidate) = estimated error + description penalty + estimated cost.
The minimum description length principle, MDL, provides a foundation for preferring an explanation that compresses both the model and the data left unexplained [
Grunwald2004
]. In MRP, this preference could favor a reusable rule over a list of exceptions. However, the result depends on the language in which description length is measured and on data quality. A short program is not automatically true or ethically preferable.
Separating description cost from execution cost matters. A very short definition may hide enormous search. Conversely, a longer program may precompile operations and run quickly. The library must be evaluated in terms of total cost over relevant tasks.
From a Local Program to a Reusable Concept
Suppose the agent discovers the same pattern across several protocols: group by identity, select the last event and interpret its type. Consolidation extracts the common part and parameterizes it with the protocol's specific fields and rules.
This pattern is a candidate for an operational notion of a concept: a composition organizing many cases that can be executed in new contexts. We do not claim that every human concept is such a program. We define a kind of knowledge that can be built and measured.
DreamCoder shows that learning libraries of programmatic abstractions and guiding search can be combined in a concrete system [
Ellis2020
]. For MRP, the distinct question would be whether diagnosing a collision can guide this induction and whether the new abstraction explicitly improves the family of distinctions available to the agent.
Program Equivalence and Rewriting
The library may contain different programs computing the same result. Eliminating redundancy would save memory and simplify selection. But establishing equivalence for general programs is neither free nor universally decidable [
Barak
We can work with identities proved in a restricted language. Equality saturation, including structures such as those used by egg, enables compact representation of many equivalent expressions and selection by cost [
Willsey2021
]. This does not authorize declaring arbitrary LLM-generated programs equivalent.
If operations have effects, arithmetic overflows or order matters, rewrite rules must include these conditions. An algebraic identity between ideal expressions may not hold for concrete execution. In a prototype, a pure and explicitly restricted core would greatly simplify verification.
Independent Validation and Contamination
The case that generated the hypothesis cannot be the main evidence that it generalizes. Nor does a test set consulted repeatedly until the candidate passes remain an independent evaluation. Research on adaptive data analysis shows why reusing evaluation results can compromise generalization [
Dwork2015
I would separate induction examples, development tests and a final set inaccessible to selection. An evaluator could return only the verdict needed for the current stage while retaining a reserve for final evaluation. All relevant attempts should also be reported, not just the last candidate.
Successful induction does not mean “a program was generated.” It means a program constructed from declared primitives repaired an identified insufficiency, passed appropriate evaluations and justified the cost of consolidation. This is the complete experimental object.
CHAPTER 11
The Rationality of Computation
Computing Is Also an Action
An agent chooses not only between actions in the world but also between internal operations. It may consult a table, execute a more precise interpreter, request a new observation or construct a hypothesis. Every option consumes time and may change the final decision.
The value of computation is the expected gain from an internal operation after subtracting its cost. For a single operation followed by a decision, we can write, without assuming a perfect solution:
ValueOfComputation = expected decision gain after computation − decision gain now − computation cost.
This formula is not a new MRP law. Metareasoning and learning policies for selecting computations already have experimental formulations, including the work of Callaway and colleagues [
Callaway2018
]. MRP would expand the repertoire of selectable operations to include constructing and consolidating interpreters.
